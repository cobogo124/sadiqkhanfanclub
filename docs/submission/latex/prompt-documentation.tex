\section{Prompt Documentation}\label{prompt-documentation}

\subsection{Purpose Of This Document}\label{purpose-of-this-document}

The coursework brief asks for a document explaining what prompts were
used and for what specific knowledge-engineering task. The repository
preserves one operational LLM prompt verbatim and preserves evidence of
a few additional prompt-driven activities indirectly through comments,
outputs, and cached files. This document separates:

\begin{itemize}
\tightlist
\item
  prompts recoverable exactly from the repository
\item
  prompt-driven tasks that are only reconstructable from repository
  evidence
\end{itemize}

Where a prompt is reconstructed rather than preserved verbatim, that is
stated explicitly.

\subsection{Exact Prompt Recoverable From The
Repository}\label{exact-prompt-recoverable-from-the-repository}

\subsubsection{Task: triple extraction from unstructured
text}\label{task-triple-extraction-from-unstructured-text}

Source:
\texttt{data\_retrieval/unstructured\_retrieval/extract\_triples.py}

Model/runtime recorded in code:

\begin{itemize}
\tightlist
\item
  local Ollama endpoint at \texttt{http://localhost:11434/api/generate}
\item
  model name: \texttt{mistral}
\item
  caching enabled through \texttt{data/caches/triples\_cache.json}
\item
  current repository setting: \texttt{USE\_LLM\ =\ False}
\end{itemize}

Repository-preserved prompt:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{\#\#\# Instruction}
\NormalTok{Extract RDF triples from the text below about London public transport.}
\NormalTok{A triple has the format: subject | predicate | object}

\NormalTok{\#\#\# Constraints}
\NormalTok{{-} ONLY extract facts explicitly stated in the text}
\NormalTok{{-} Do NOT infer, guess, or add external knowledge}
\NormalTok{{-} Use clean short labels: "Victoria line" not "the Victoria line"}
\NormalTok{{-} Use camelCase predicates: "operatedBy" not "operated by"}
\NormalTok{{-} Use natural labels with spaces: "Elizabeth line" not "ElizabethLine" or "Elizabeth\_line"}
\NormalTok{{-} Do NOT prefix with "subject:" or "predicate:" or "object:"}
\NormalTok{{-} Maximum 10 triples}
\NormalTok{{-} If no facts can be extracted, return: NONE}

\NormalTok{\#\#\# Examples}
\NormalTok{Victoria line | operatedBy | Transport for London}
\NormalTok{DLR | openedIn | 1987}
\NormalTok{Jubilee line | hasStop | Westminster}
\NormalTok{Oyster card | acceptedOn | London Underground}
\NormalTok{Zone 1 | contains | Kings Cross St Pancras}

\NormalTok{\#\#\# Text}
\NormalTok{\{passage\}}

\NormalTok{\#\#\# Triples}
\end{Highlighting}
\end{Shaded}

Knowledge-engineering task supported:

\begin{itemize}
\tightlist
\item
  extraction of candidate subject-predicate-object statements from
  textual sources
\item
  preparation of unstructured facts for later RDF mapping
\end{itemize}

Why this prompt is useful:

\begin{itemize}
\tightlist
\item
  it constrains the model to explicit facts
\item
  it normalizes predicate style for later mapping
\item
  it limits output length
\item
  it supports downstream validation against spaCy-recognized entities
\end{itemize}

\subsection{Prompt Execution Notes}\label{prompt-execution-notes}

The repository currently uses cached LLM outputs rather than live
generation during a normal run:

\begin{itemize}
\tightlist
\item
  \texttt{USE\_LLM\ =\ False} in \texttt{extract\_triples.py}
\item
  \texttt{data/caches/triples\_cache.json} contains 563 cached
  extraction entries
\end{itemize}

This is good for reproducibility in a marking environment, but it also
means the exact dialogue history that originally produced the cache is
not fully recoverable from the repository alone.

\subsection{Conclusion}\label{conclusion}

The repository preserves one exact operational prompt and preserves the
outputs of several other prompt-dependent tasks, but it does not
preserve every search query or chat transcript used during knowledge
engineering. For submission purposes, the safest and most honest
position is:

\begin{itemize}
\tightlist
\item
  present the triple-extraction prompt verbatim
\item
  identify the other prompt-driven tasks clearly
\item
  label reconstructed prompts as reconstructed rather than original logs
\end{itemize}

That approach keeps the documentation complete without inventing
provenance that the repository does not actually contain.
